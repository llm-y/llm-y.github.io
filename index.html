Agent AI di terminal, dengan model pilihan Anda

llmy membaca dan mencari file, mengedit kode, dan menjalankan perintah di folder proyek Anda. Bawaannya model lokal lewat Ollama; Claude, Google Gemini, dan API kompatibel OpenAI juga bisa dipakai, termasuk API yang hanya bisa teks. Memorinya cukup satu file AGENTS.md, tanpa database. Setiap perubahan ditanyakan dulu kecuali Anda sudah mengizinkannya.

Pasang Baca manual

Versi terbaru untuk Linux, macOS, dan Windows. Satu file sekitar 2 MB, lisensi GPL-3.0.

Instalasi

  1. Pasang llmy

    curl -fsSL https://ll.my.id/install.sh | sh

    Terpasang di ~/.local/bin/llmy. Checksum diperiksa sebelum dipasang. Butuh git. Lihat skripnya.

    irm https://ll.my.id/install.ps1 | iex

    Jalankan di PowerShell. llmy butuh Git for Windows (git dan tool bash). Lihat skripnya.

    cargo install --locked --git https://github.com/llm-y/agent

    Butuh Rust 1.91 atau lebih baru dan compiler C.

  2. Siapkan model

    Pasang Ollama, lalu unduh model yang mendukung tool. Model bawaan llmy sekitar 6,6 GB.

    ollama pull qwen3.5:9b

  3. Jalankan di folder proyek

    cd proyek-saya
llmy

Memperbarui: jalankan lagi perintah instalasinya. Menghapus: hapus file llmy dan folder sesinya.

Server di jaringan lokal seperti vLLM atau LM Studio bisa dipakai lewat http:// tanpa kunci. Bila kunci terpasang, kunci itu tidak dikirim ke sana, dan isi percakapan tidak terenkripsi di jalan.

llmy -m openai/nama-model --url http://192.168.1.5:8000/v1

llmy -m deepseek/deepseek-flash

Dengan model cloud, pesan Anda dan isi file yang dibaca dikirim ke penyedianya dan dikenai biaya. llmy menampilkan alamat tujuannya saat mulai.

Pada Claude Opus 5 dan 5.5, Sonnet 5.5, dan Fable 5, llmy mengaktifkan model cadangan: permintaan yang ditolak pengklasifikasi keamanan dicoba lagi oleh model lain yang dipilih Anthropic, dan hal itu diberitahukan bila terjadi di jawaban tersebut.

API yang hanya bisa teks

Agent biasanya butuh API dengan tool calling native, yaitu model mengirim panggilan tool sebagai data terstruktur. llmy tidak mewajibkannya. Bila server hanya menerima dan membalas teks, model menulis panggilannya di dalam jawaban:

<use_tool name="read">
{"path": "hitung.py"}
</use_tool>

llmy membaca blok itu, memeriksa izinnya, menjalankan tool-nya, lalu mengirim hasilnya sebagai pesan teks. Tool, izin, dan sesinya sama dengan mode native. Tidak perlu mengatur apa pun:

llmy -m openai/nama-model --url https://alamat-server/v1
--toolsYang terjadi
auto (bawaan)Native didahulukan. Pindah ke teks bila native terbukti gagal dan teks terbukti jalan; llmy memberi tahu saat itu
nativeSelalu native, tanpa pemeriksaan
textSelalu lewat teks, tanpa pemeriksaan
  • Pada server selain Ollama dan API resmi, auto memeriksa sekali dengan satu sampai empat permintaan kecil tanpa isi percakapan Anda. Hasilnya diingat 30 hari per server dan model, atau satu hari bila tidak jelas.
  • Ollama tidak diperiksa: llmy pindah ke teks bila Ollama menolak tool untuk model itu.
  • Protokolnya tetap harus Ollama, OpenAI (/v1/chat/completions), atau Anthropic (/v1/messages). API dengan format sendiri belum bisa dipakai langsung.
  • Mode teks bergantung pada kepatuhan model. Dalam uji kecil di server yang membuang tool, qwen3.5 9b berhasil 3 dari 3, gemma4 12b 1 dari 1, nemotron 4b 1 dari 2, dan qwen2.5 3b 0 dari 2.

Izin ini bukan sandbox. Perintah bash yang Anda setujui berjalan dengan hak akses Anda dan bisa menjangkau seluruh komputer.

grep mencari isi file atau nama file. File tersembunyi, symlink, dan folder hasil build seperti target dan node_modules dilewati. Bila model memakai bash hanya untuk melihat atau mencari file, llmy mengarahkannya ke read atau grep sebelum bertanya kepada Anda, paling banyak tiga kali per giliran.

File rahasia dikenali dari namanya, misalnya .env, id_rsa, *.pem, dan credentials.json. Pengenalan ini tidak lengkap; jangan mengandalkannya sebagai satu-satunya pelindung.

Mode auto (--auto, /auto, atau Shift+Tab) menyetujui edit, bash, memori, dan tool internet tanpa bertanya. Path di luar folder kerja, di .git, atau file rahasia tetap ditanya; pada -p tindakan itu ditolak.

Satu giliran tidak dibatasi jumlah langkahnya. Giliran berakhir bila model selesai, Anda menekan Esc, izin ditolak, atau delapan tool gagal berturut-turut (agar model yang macet tidak berputar selamanya).

Pilihan "selalu" untuk bash hanya berlaku untuk perintah yang persis sama, dan semua pilihan "selalu" hilang saat llmy ditutup. Pada mode -p, tindakan tanpa izin menghentikan pekerjaan dengan kode keluar 1, kecuali menyimpan memori: itu hanya dilewati.

Verifikasi setelah edit

Setelah langkah yang mengubah file, llmy sendiri menjalankan pemeriksaan proyek dan menempelkan hasilnya ke hasil edit, sehingga model langsung melihat galat build. Model tidak perlu ingat menjalankan build.

ProyekPerintahDipicu oleh
Rust (Cargo.toml)cargo check --all-targets*.rs, Cargo.toml
Go (go.mod)go build ./... && go vet ./...*.go, go.mod
TypeScriptskrip typecheck di package.json, atau tsc --noEmit*.ts, *.tsx, tsconfig.json
Pythonpython3 -m py_compile untuk file yang diubah (sintaks saja)*.py
JavaScript (mis. croot.js)node --check tiap file yang diubah, juga sebagai modul ES (sintaks saja, tidak dijalankan)*.js, *.mjs, *.cjs
LaTeXKompilasi draft file utama (yang punya \documentclass dan memuat file itu) dengan pdflatex, atau xelatex/lualatex bila dipakai; tanpa shell escape, keluaran ke folder sementara*.tex, *.sty, *.cls
Lainnya--verify "make test" atau LLMY_VERIFYSetiap file
  • Build bisa menjalankan kode proyek (build.rs, skrip npm), jadi pemeriksaan bawaan ditanya seperti bash. py_compile, node --check, dan kompilasi draft LaTeX tanpa shell escape tidak menjalankan kode proyek, jadi tidak ditanya. Galat LaTeX diringkas menjadi baris file.tex:baris: pesan dan l.N, bukan log ratusan baris. Pengecualian lain: mode auto atau --allow bash. Pilih "selalu" agar tidak ditanya lagi; menolak mematikannya untuk sesi itu. Perintah yang Anda tulis sendiri dengan --verify dijalankan tanpa tanya. Pada -p tanpa izin, pemeriksaan dilewati.
  • Isi file yang gagal diperiksa diingat. Bila model menulis isi yang persis sama lagi, tulisan itu ditolak, sampai ada pemeriksaan yang lulus.
  • Empat pemeriksaan gagal berturut-turut tanpa kemajuan (jumlah galat tidak berkurang) menghentikan giliran. Refactor lintas file yang galatnya terus berkurang tidak dihentikan. Ketik "lanjutkan" untuk mencoba lagi.
  • Pemeriksaan yang perintahnya tidak terpasang (exit 127) dimatikan untuk sesi itu.
  • Bila pemeriksaan gagal, llmy menempelkan potongan kode di sekitar lokasi galat (mis. src/a.rs:12), jadi model tidak perlu membaca file lagi.
  • Uji di akhir giliran. Saat model menyatakan selesai dan ada file yang berubah, llmy menjalankan uji proyek: cargo test, pytest atau python3 -m unittest (bila ada test_*.py), npm test atau node --test, dan untuk LaTeX dua kali kompilasi untuk menemukan \ref yang tidak terdefinisi. Bila gagal, hasilnya dikembalikan ke model, paling banyak dua kali; setelah itu giliran berhenti dengan galat. Uji menjalankan kode proyek, jadi ditanya seperti bash (kecuali LaTeX). Pada pengukuran 16 tugas di Rust, Python, JavaScript, dan LaTeX dengan qwen3.5:9b, ini (bersama potongan kode di lokasi galat) menaikkan keberhasilan dari 33/48 ke 45/48 dan menurunkan "mengaku selesai padahal salah" dari 15/48 ke 3/48.

Mode BDI

Bawaannya satu loop dengan satu model: model memilih tool, llmy menjalankannya, sampai model selesai. Dengan --mode bdi (atau /mode bdi, atau llmy api mode bdi), kerjanya dibagi ke beberapa agent:

  1. Perencana membaca peta proyek (signature fungsi, tipe, dan kelas beserta nomor barisnya) lalu memecah permintaan menjadi beberapa tujuan kecil (desire), masing-masing satu atau dua file, beserta urutannya. Dipanggil dengan suhu rendah dan keluaran JSON, tanpa tool. Bisa model lain lewat --plan, misalnya model cloud gratis yang besar, sementara pekerjanya model lokal.
  2. Deliberasi memilih tujuan berikutnya bila ada beberapa kandidat atau ada pendekatan yang sudah gagal. Satu kandidat tanpa kegagalan dipilih tanpa memanggil model.
  3. Pekerja mengerjakan satu tujuan dengan context baru: hanya permintaan Anda, tujuan itu, yang sudah selesai, galat terakhir, dan isi file targetnya. Tool dan izinnya sama dengan mode biasa.
  4. llmy sendiri menilai hasilnya dari verifikasi setelah edit. Gagal dicoba lagi sampai tiga kali dengan galatnya; bila buntu atau isinya berulang, file dikembalikan ke isi sebelum tujuan itu (file baru dihapus), pendekatan yang gagal dicatat, dan tujuan direncanakan ulang sekali sebelum ditinggalkan.
  5. Eskalasi: sebelum direncanakan ulang, perencana menerima galat dan diff yang gagal, lalu mencari akar masalahnya. Diagnosis dan langkah barunya dipakai pekerja berikutnya. Pasangan yang cocok: --plan model cloud gratis sebagai arsitek, model lokal sebagai pekerja.

Sesi hanya menyimpan permintaan Anda dan ringkasan hasil, bukan percakapan pekerja. Pada -p, tujuan yang tidak tercapai membuat kode keluar 1.

Pada pengukuran dengan qwen3.5:9b (dua refactor Rust lintas file, lima kali), mode BDI dan mode loop sama-sama benar 9 dari 10. Untuk tugas sekecil itu BDI belum lebih baik, jadi bawaan tetap loop.

Sub-agent

Di mode biasa, model bisa menyerahkan sub-tugas ke sub-agent lewat tool task: misalnya satu modul dari pekerjaan besar, atau pencarian luas yang rinciannya tidak perlu masuk percakapan utama. Sub-agent mulai dengan context baru, memakai tool dan izin yang sama, bekerja sampai selesai, lalu mengembalikan laporan singkat beserta daftar file yang diubahnya. Model utama hanya menerima laporan itu, jadi context-nya tetap kecil.

  • Satu tingkat saja: sub-agent tidak bisa membuat sub-agent lagi.
  • --sub <model> menjalankan sub-agent dengan model lain, misalnya model besar sebagai pengarah dan model lokal sebagai pelaksana.
  • Percakapan sub-agent tidak disimpan ke sesi; yang tersimpan hasil task-nya.
  • Sub-agent yang menulis berjalan satu per satu, karena semuanya bekerja di folder yang sama. Sub-agent baca-saja (readonly) hanya mendapat read, grep, head, dan tail; beberapa sekaligus dalam satu jawaban dijalankan paralel.

Lain-lain tentang tool

  • read dengan symbol langsung membuka definisi tanpa menebak nomor baris: fungsi, struct, atau kelas di Rust, Python, dan JavaScript (termasuk const f = () =>); judul bagian, \label, atau \newcommand di LaTeX; kunci sitasi di BibTeX. Bila namanya ada di beberapa file, llmy menyebutkan semuanya.
  • Bahasa utama llmy: Rust, JavaScript (croot.js), LaTeX, dan Python. Pengenal definisinya diukur terhadap parser resmi (syn, acorn, ast) dan cocok 100%. Go juga diukur (100%); bahasa lain memakai pola yang sama tetapi belum diukur.
  • edit dengan edits mengganti beberapa bagian satu file sekaligus. Semua bagian harus cocok; bila satu gagal, file tidak diubah.
  • edit toleran terhadap salah indentasi dan spasi di ujung baris: bila teks old tidak cocok persis tetapi cocok per baris dengan selisih indentasi yang sama, dan hanya di satu tempat, perubahan diterapkan dengan indentasi file. Bila tetap tidak cocok, galatnya menampilkan isi file saat ini di sekitar baris yang mirip.
  • Argumen tool yang cacat (dibungkus ```json, koma di akhir, kutip tunggal, ganti baris mentah di dalam string, True/None ala Python) diperbaiki sebelum ditolak.
  • Opsional (LLMY_MAP=on): pesan pertama sesi diawali peta proyek (signature dan nomor barisnya), dan giliran berikutnya diawali catatan file yang sudah diubah serta status pemeriksaan terakhir. Tidak aktif secara bawaan karena pada pengukuran 16 tugas tidak menaikkan keberhasilan (43/48 vs 45/48 tanpa peta).
  • Git wajib: folder kerja yang belum menjadi repo di-git init otomatis (kecuali $HOME dan /, yang berjalan tanpa fitur git). llmy menyimpan snapshot di awal tiap giliran dan setiap kali uji berjalan, di refs/llmy/<sesi>: branch, HEAD, index, hook, dan git log Anda tidak berubah. Lihat langkahnya dengan git log refs/llmy/<sesi>. Bila giliran berhenti karena macet padahal versi sebelumnya lulus lebih banyak uji, file yang diubah llmy dikembalikan ke versi itu; file lain tidak disentuh.
  • Penjaga antarmuka: write utuh atas file yang sudah ada tetapi belum dibaca ditolak (model diminta membacanya dulu), dan perubahan export menjadi module.exports ditolak dengan petunjuk cara menguji modul ES dari shell. Bila edit menghilangkan nama publik (export JavaScript, pub Rust, def/class Python) atau mengubah signature-nya, model diberi peringatan; editnya tetap berlaku. Pembandingnya isi file saat sesi dimulai (snapshot git), juga setelah -c. Matikan dengan LLMY_IFACE=off.
  • Deteksi siklus: model yang mengulang urutan 2–4 panggilan dengan hasil yang sama tiga kali diperingatkan; bila masih mengulang, giliran dihentikan. Matikan dengan LLMY_CYCLE=off.
  • Batas waktu (LLMY_BUDGET=<detik>, bawaan mati): pada 80% batas, model diminta berhenti menjelajah dan menyelesaikan; pada 95% giliran dihentikan (dengan kembali ke versi terbaik bila ada). Berguna untuk llmy -p di skrip yang punya batas waktu.
  • script menjalankan program Python (atau Node dengan lang: node) di folder kerja, untuk perubahan mekanis yang sama di banyak file: mengganti nama fungsi di semua file, mengganti pola, memperbarui import. Satu panggilan menggantikan puluhan edit, jadi lebih hemat token. Model menerima daftar file yang berubah dan diff ringkas (hanya baris yang berubah), file itu diverifikasi, dan /undo mengembalikannya. Export ESM yang diganti CommonJS dikembalikan, sama seperti pada edit. Izinnya seperti bash, karena kodenya bisa berbuat apa saja.
  • File yang diubah bash (misalnya sed -i, mv, generator kode) dikenali dengan memindai folder kerja sebelum dan sesudah perintah. File itu diverifikasi seperti hasil edit, ikut /undo dan rollback mode BDI, dan daftarnya diberikan ke model. Folder hasil build dan file di atas 1 MB tidak disimpan isinya.

Tool internet

Tool ini memakai klien HTTP bawaan llmy, tanpa program luar. Isi permintaan dikirim ke layanan yang bersangkutan, jadi setiap panggilan meminta izin.

Halaman panjang tidak dikirim utuh ke model. HTML diambil isi utamanya (<main> atau <article>; menu, sidebar, footer, dan form dibuang), lalu dibagi per bagian. Tanpa argumen tambahan, model menerima bagian pertama beserta daftar judul bagian. Dengan find (misalnya pertanyaan atau kata kunci), llmy memilih paragraf yang paling cocok di komputer sendiri (BM25, tanpa jaringan dan tanpa model); dengan part, model membuka bagian tertentu. Halaman yang sudah diambil disimpan 15 menit selama llmy berjalan, jadi mencari hal lain atau membuka bagian lain tidak mengambil ulang. Berlaku untuk curl, spider, firecrawl, dan brightdata. Pada 6 halaman dokumentasi asli, jawaban yang dicari terbawa di 6 halaman dengan find (rata-rata 4,8 KB), sedangkan 12.000 byte pertama hanya memuatnya di 3 halaman (rata-rata 11,4 KB).

Tool yang butuh kunci hanya ditawarkan ke model bila kuncinya ada di env, dan kunci itu tidak terlihat oleh perintah bash. Tool lokal head dan tail membaca awal atau akhir file; essence mengambil URL, email, DOI, dan kata kunci dari teks tanpa jaringan.

export TAVILY_API_KEY=kunci-anda
llmy --allow web -p "cari berita terbaru tentang Rust 2026"

tavily, exa, linkup, firecrawl, scopus, dan brightdata ditulis menurut dokumentasi masing-masing layanan, tetapi belum diuji dengan kunci asli.

Instruksi proyek

Tulis aturan proyek di AGENTS.md (atau CLAUDE.md bila tidak ada). llmy membaca file itu dari akar git sampai folder kerja, ditambah instruksi pribadi di ~/.config/llmy/AGENTS.md. Totalnya dibatasi sekitar 8.000 byte; yang terdekat dengan folder kerja didahulukan.

Memori

Memori llmy adalah daftar fakta di bagian ## Memory pada AGENTS.md. Tidak ada database, embedding, atau proses latar, dan model tidak dipanggil khusus untuk mengurusnya. Anda bisa membaca, mengedit, atau menghapusnya seperti file biasa.

CakupanFileDibaca
ProyekAGENTS.md di akar proyek (atau CLAUDE.md bila hanya itu yang ada)Di proyek itu
Semua proyek~/.config/llmy/AGENTS.md (Windows: %APPDATA%\llmy)Di setiap proyek

Memori semua proyek otomatis terbawa saat Anda pindah proyek. Memori proyek bisa ikut masuk git. Cukup katakan, misalnya:

Ingat: proyek ini pakai pnpm
Ingat untuk semua proyek: jawab singkat dalam bahasa Indonesia
  • Model menyimpan dan mengganti fakta yang usang. Bila pesan Anda diawali "ingat" tetapi model lupa menyimpannya, llmy menyimpan kalimat Anda sendiri.
  • Duplikat ditolak, fakta yang mirip harus diganti atau dipertahankan secara tegas, dan isinya dibatasi 40 fakta per file.
  • Setiap penyimpanan menampilkan diff dan meminta izin. Pilih "selalu", atau pakai --allow memory, agar sepenuhnya otomatis.
  • Yang tampak seperti kunci atau sandi ditolak. Pengenalan ini tidak lengkap, jadi jangan menyuruh llmy mengingat rahasia.
  • Memori baru dibaca di sesi berikutnya atau sesudah /clear.

Sesi dan context

Percakapan, termasuk isi file yang dibaca, disimpan di ~/.local/state/llmy/sessions (Windows: %LOCALAPPDATA%\llmy) dan tidak dihapus otomatis. Pada 80% context, percakapan diringkas otomatis. Pesan Anda disalin apa adanya ke ringkasan, dipotong bila panjang.

Tanya jawab

Apakah kode saya dikirim ke internet?

Dengan model bawaan, tidak: llmy hanya menghubungi Ollama di komputer sendiri. Dengan model cloud, ya: pesan dan isi file yang dibaca dikirim ke penyedia model itu. Perintah bash yang Anda setujui juga bisa mengakses jaringan.

Seberapa andal hasilnya?

Model lokal 9B cocok untuk perubahan kecil dan terarah; untuk tugas besar pakai model yang lebih kuat. Model mana pun bisa salah atau mengarang, jadi baca diff dan jalankan uji sebelum memakai hasilnya.

Model apa yang bisa dipakai?

Paling baik model yang mendukung tool. Untuk Ollama, cek dengan ollama show nama-model: pada bagian Capabilities ada tools. Model atau server tanpa dukungan itu dipakai lewat mode teks.

API saya hanya chat biasa tanpa tool calling. Bisa?

Bisa, asalkan formatnya Ollama, OpenAI, atau Anthropic dan modelnya cukup patuh mengikuti format. Lihat API yang hanya bisa teks. Bila muncul pesan bahwa model tidak memakai tool, coba model yang lebih kuat atau paksa dengan --tools text.

Muncul "tidak bisa terhubung"

Pastikan Ollama berjalan (ollama serve) dan alamatnya benar. Untuk Ollama di komputer lain pakai --url http://alamat:11434; sambungannya tidak terenkripsi, jadi lewatkan jaringan tepercaya atau terowongan SSH.

Perintah llmy tidak ditemukan

Di Linux dan macOS tambahkan export PATH="$HOME/.local/bin:$PATH" ke berkas profil shell. Di Windows buka terminal baru.
